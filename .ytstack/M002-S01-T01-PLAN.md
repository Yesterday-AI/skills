wrong font. Gating task for S01.

## What this does

Context from reading the renderer:
- `references/render_template.html` imports `@excalidraw/excalidraw@0.18.0` and calls
  `exportToSvg`. In 0.18 the font IDs are: **1 = Excalifont (hand-drawn)**,
  **2 = Nunito (normal sans)**, **3 = Comic Shanns Mono (code)** -- NOT the old
  Virgil/Helvetica/Cascadia mapping. This task confirms that empirically.
- The template hard-sets `appState.viewBackgroundColor = "#ffffff"` and defaults to
  `--theme dark` (a CSS invert filter). Note this for the cream-bg work; T01 itself
  renders with `--theme light` to read true colors.

Steps:
1. Hand-write `/tmp/font-probe.excalidraw` (valid wrapper: `type/version/elements/appState/files`)
   with three free-floating `text` elements, the same string e.g.
   "Hand-drawn? Sphinx 123" -- one with `fontFamily: 1`, one `2`, one `3`,
   y-offset ~80px apart, `fontSize: 28`, `strokeColor: "#1f1f1f"`.
2. Render: `uv run python render_excalidraw.py /tmp/font-probe.excalidraw --theme light`.
3. Read the PNG. Confirm: ID 1 renders as a genuine hand-drawn font (Excalifont
   glyphs, not a serif/box fallback), ID 2 as a clean sans, ID 3 as monospace.
4. Record in `.ytstack/KNOWLEDGE.md`: the verified hand-drawn ID (expected `1`),
   the 0.18 font-id mapping, and the two renderer gotchas (forced white bg in
   template; default dark theme + invert filter) so S01-T02/T03 + S02 don't trip.
